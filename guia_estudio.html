Guía de Defensa: App BuscaYa

Resumen técnico, arquitectura, componentes y respuestas clave para la defensa del parcial de programación móvil.

Proyecto: BuscaYa
Plataforma: Android (Kotlin)
Localidad: Villa del Rosario
Paradigma: Declarativo (Compose)

1. Resumen de la Aplicación

BuscaYa es una aplicación móvil nativa diseñada para centralizar búsquedas locales en la ciudad de Villa del Rosario. Su funcionalidad base consiste en:


  • Visualizar farmacias de turno en tiempo real en la pantalla principal.
  • Realizar búsquedas dinámicas de comercios y productos mediante un buscador inteligente que consume un motor de búsqueda híbrida.
  • Visualizar detalles completos de farmacias y resultados de búsqueda (dirección, teléfono, imágenes, horarios, etc.).

2. Arquitectura de Software: MVVM

La aplicación implementa el patrón de arquitectura recomendado por Google: MVVM (Model-View-ViewModel), el cual promueve la separación de responsabilidades, la facilidad de mantenimiento y la testeabilidad de la app.

VISTA (UI) - Jetpack Compose

MainActivity, FarmaciaScreen, PharmacyListItem

Dibuja la UI reactivamente según el estado expuesto por el ViewModel.

↑ Observa el Estado / Emite Eventos ↓

VIEWMODEL - FarmaciaViewModel

FarmaciaViewModel.kt

Expone el estado de la UI como StateFlow. Lanza Corrutinas en viewModelScope.

↑ Solicita Datos / Retorna Resultados ↓

MODELO Y CAPA DE DATOS (Repositories & Retrofit)

FarmaciaRepository, SearchRepository, RetrofitInstance

Representa las entidades (Farmacia, SearchResult) y la lógica para consumir la API externa.

Desglose de la Implementación:


1. View (Vista): Escrita usando Jetpack Compose. La interfaz principal es FarmaciaScreen. Mediante collectAsState(), la UI se suscribe a los flujos de estado del ViewModel (como farmacias, searchResults, isLoading). Cuando el estado cambia, la UI se **recompone** automáticamente.


2. ViewModel: FarmaciaViewModel hereda de ViewModel de Android Jetpack. Sirve como puente entre los datos y la vista. Mantiene las variables de estado privadas (MutableStateFlow) y expone versiones de solo lectura (StateFlow) para proteger la integridad del estado.


3. Model (Modelo) & Data Source: Representado por las clases de datos de Kotlin (Farmacia y SearchResult) anotadas con @SerializedName para mapear las propiedades JSON automáticamente usando GSON.

3. Stack Tecnológico

Kotlin

  • Lenguaje de programación nativo y moderno oficial para Android.
  • Tipado estático, seguro contra nulos (Null-safety).

Jetpack Compose (M3)

  • UI declarativa nativa moderna.
  • Material Design 3 (M3) para un look premium.
  • Gestión de estado simplificada en Compose.

Retrofit & GSON

  • Cliente HTTP type-safe para peticiones de red.
  • Custom Gson Deserializer para manejar formatos de JSON dinámicos y resilientes.

Kotlin Coroutines & Flow

  • Programación asincrónica estructurada.
  • Uso de suspend fun para no bloquear el hilo principal (UI thread).

Coil (Compose-Coil)

  • Biblioteca moderna de carga de imágenes.
  • Carga asincrónica de imágenes desde URLs remotas (HTTP) optimizada y rápida.

4. ¿Cómo funciona la App? (Flujo de Datos)

Es vital que describas el flujo paso a paso si el profesor te pide explicar qué ocurre tras bambalinas:


  1. Inicio de la App:
    • MainActivity ejecuta enableEdgeToEdge() para expandir la UI debajo de las barras de estado del sistema.
    • Establece el contenido principal renderizando BuscayaTheme y FarmaciaScreen().
    • Se instancia el FarmaciaViewModel mediante delegación de Compose.
  2. Carga Inicial de Farmacias (GET /api/farmacias_turno_android):
    • Un bloque LaunchedEffect(Unit) en FarmaciaScreen se dispara una única vez al entrar a la pantalla, llamando a viewModel.obtenerFarmacias().
    • El ViewModel cambia el estado _isLoading.value = true y arranca una corrutina (viewModelScope.launch).
    • Llama al método getFarmaciasEnTurno() del Repositorio.
    • El repositorio consume la API usando Retrofit (RetrofitInstance.api.getFarmaciasEnTurno()).
    • El JSON devuelto se procesa en el deserializador customizado FarmaciaListDeserializer. Este busca si el JSON es un Array directo o si tiene el campo clave "farmacias", "results" o "data" para extraer la lista de forma robusta.
    • El repositorio retorna la lista parseada de objetos Farmacia. El ViewModel guarda esta lista en _farmacias.value y pone _isLoading.value = false.
    • La UI de Compose reacciona a los cambios en el flujo de estado y dibuja las tarjetas en el LazyColumn de farmacias.
  3. Búsqueda Inteligente (GET /api/hybrid-search-android?q=query):
    • El usuario escribe en el input y presiona "Buscar" en el teclado virtual (evento onSearch / ImeAction.Search).
    • Se dispara viewModel.buscarLocales(searchQuery).
    • Se ejecuta una corrutina que invoca a SearchRepository.hybridSearch(query).
    • La API devuelve una lista de SearchResult que se almacena en _searchResults.value.
    • Compose recompone la pantalla mostrando los resultados en la sección superior sobre un fondo que facilita su lectura.
  4. Visualización del Detalle:
    • Al presionar en un comercio buscado o una farmacia, se actualizan las variables locales de estado en Compose (selectedSearchResult o selectedFarmacia).
    • Esto despliega de inmediato un cuadro de diálogo detallado (Dialog o AlertDialog) con información enriquecida, incluyendo mapa conceptual o foto usando Coil.

5. Banco de Preguntas para el Examen (Frecuentes)

P1: ¿Por qué usas corrutinas en lugar de llamar a la API directamente en el hilo de la UI?
Llamar a un endpoint HTTP es una operación bloqueante y lenta. Si lo hiciéramos en el hilo principal de la UI (Main Thread), la aplicación se congelaría e incluso Android lanzaría una excepción NetworkOnMainThreadException. Las Corrutinas permiten ejecutar tareas en segundo plano usando un hilo optimizado para E/S (como Dispatchers.IO internamente en Retrofit) de forma asíncrona, manteniendo la UI fluida.
P2: ¿Qué es Jetpack Compose y cuál es la diferencia con el sistema de vistas tradicional (XML)?
Jetpack Compose es un kit de herramientas moderno de tipo declarativo. En XML describimos una jerarquía estática de vistas y debemos mutarla manualmente usando referencias en el código (como findViewById o binding). En Compose, en cambio, describimos la interfaz de usuario en función de un estado actual. Si el estado cambia, la UI se recompone automáticamente. No manipulamos los widgets directamente, sino que cambiamos el estado.
P3: ¿Por qué es necesario un deserializador personalizado (FarmaciaListDeserializer)?
La API externa a la cual consumimos puede variar su formato de respuesta (por ejemplo, a veces devuelve directamente un array JSON [...] y otras veces devuelve un objeto con un array dentro de un campo como {"farmacias": [...]} o {"data": [...]}). El deserializador personalizado intercepta la lectura de Gson y valida dinámicamente el formato para extraer los datos correctos sin que la app falle.
P4: ¿Qué son StateFlow y MutableStateFlow y por qué se usan en el ViewModel?
MutableStateFlow es un contenedor de estado de la biblioteca de Corrutinas que siempre retiene el último valor y emite actualizaciones a sus suscriptores. Usamos StateFlow (de solo lectura) expuesto públicamente para asegurar que la vista no modifique el estado directamente, respetando el flujo unidireccional de datos (UDF - Unidirectional Data Flow). La vista solo interactúa llamando a funciones públicas del ViewModel.
P5: ¿Cómo funciona Coil para cargar imágenes?
Coil (Coroutine Image Loader) está construido nativamente para Kotlin y optimizado para Compose. Cuando usamos el componente composable AsyncImage, Coil toma la URL de la imagen, descarga los datos de forma asíncrona utilizando corrutinas, los decodifica, gestiona la caché en memoria y almacenamiento para no re-descargarla la próxima vez, y los dibuja en pantalla de forma fluida.
💡 CONSEJO PARA MAÑANA: Si el profesor pregunta qué agregaste o modificaste recientemente, menciona la separación de las Farmacias de Turno fijas (para que siempre estén visibles al usuario) de la sección superior que maneja las búsquedas dinámicas de comercios y farmacias. Esto mejoró significativamente la experiencia del usuario final.

6. Consejos Prácticos para la Defensa

  • Seguridad al hablar: Enfatiza que estás usando buenas prácticas de desarrollo moderno de Android (Kotlin moderno, UI declarativa en Compose, arquitectura MVVM limpia). Esto le encanta a los profesores de universidad.
  • Flujo Unidireccional de Datos (UDF): Si te piden dibujar o explicar cómo se conectan las partes, usa esta idea: "Los datos fluyen hacia abajo (ViewModel -> UI en forma de estado) y los eventos fluyen hacia arriba (UI -> ViewModel en forma de llamadas a funciones)".
  • Resiliencia: Explica que la app maneja errores con bloques try-catch y estados de error explícitos que se muestran de forma amigable al usuario en lugar de colgarse ("crashear").
